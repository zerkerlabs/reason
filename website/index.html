Deterministic authorization for AI agents

Company rules, enforced before agents act.

Models handle ambiguous work. Zerker Reason checks the proposed action against governed facts, explicit rules, authority, and time, with no model in the decision path, and returns a certificate anyone can verify without trusting the runtime. When Reason enforcement is configured, Zerker Gateway forwards only the exact independently verified MCP call.

Open source · local first · deterministic · v0.3 · View the source

One policy bundle for every agent tool.

Teams should not have to duplicate company rules for every model vendor and coding agent. Keep the files teams already use (AGENTS.md, CLAUDE.md, skill files, security policies); a human-reviewed manifest and typed policy template lock into one bundle with a digest, and every action is authorized against that bundle with an outcome of authorized, insufficient evidence, denied, or conflicted. Only authorized can execute.

Inspect the decision yourself.

No daemon, account, network, wall clock, or LLM is required for the symbolic check.

$ cargo run -- authorize examples/authorize-deploy.json --certificate-out authorization.json
$ cargo run -- verify-authorization examples/authorize-deploy.json authorization.json

The facts Reason checks come from governed memory (ZMem); the certificate is preserved as a signed receipt by Treeship; Zerker Gateway enforces it on the exact call. Apache 2.0.
